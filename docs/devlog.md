## 2026-11-11　從一個原型開始

- **起點**：想做一款塔防遊戲，要有隨機地圖、可以蓋兵力和建築、可以升級，兵力之間要有單位碰撞，而且對電腦負擔不大
- 先做了一個**單檔 2D Canvas 原型**（現在放在 `prototype/`）：隨機路徑地圖、箭塔／砲塔／冰塔／兵營／金礦、三級升級、士兵碰撞
- **參考作品**：They Are Billions（大量屍潮）、Wool at the Gates（毛線手工風）
- 決定先把**引擎和開發環境**打好，再慢慢開發

### 選技術
- 引擎：**Web + Three.js**（3D 小場景）。原本推薦 PixiJS，但選了 3D 之後改用 Three.js
- 理由：可以在內建瀏覽器直接執行、截圖、除錯，方便一起開發
- 用 winget 安裝 Node.js LTS，專案用 TypeScript + Vite

### 引擎完成的東西
- **模擬和畫面分離**：固定每秒 30 tick，畫面插值
- **單位用 typed arrays（SoA）**，搭配**空間雜湊**做碰撞與索敵
- **流場尋路**：所有敵人共用一張路線圖，繞路太遠就會拆牆
- **InstancedMesh**：每種單位只要一次 draw call
- **毛線風格**：程式產生的針織貼圖、縫線風格介面、毛線軸城堡和塔、綿羊士兵
- **開發者沙盒**：地圖種子、時間倍率、單步、生成屍潮、免費建造、流場顯示
- 壓力測試：2000 隻單位時模擬約 2.4ms／tick

## 2026-11-12　大量發想

一整天的腦力激盪，從主題、經濟、種族到終局，主要轉折：

1. **毛線 vs 火**：毛線怕火 → 敵人帶著火來 → 主題變成**守護大自然**
2. **經濟**：不要傳統的食物／木頭／金礦，改成毛線經濟；**資源無限但產量受限**
3. **挑戰性**：「不是無腦堆資源」成為第一條設計支柱
4. **規則簡單**：使用者希望「無腦一點、別太細節」，例如農田不需要輪作
5. **主角**：從「農民」到「動物小村落」，最後決定是**擬人化動物**；不把動物的特色拆下來當裝甲，而是**各種族運用自己的天賦**
6. **外交**：外交館＋親密度，跨局累積；外交分成**戰場救助**和**外交使者**兩種
7. **時間**：月份太久 → 週＋季節；日夜太強制 → 融入**攻擊主角附帶的天氣事件**
8. **終局**：大後期加成奇觀，最後一場**總攻擊，撐過去就贏**
9. **敵人**：好壞種族分開；現實動物的敵人打贏後有機會救回良善個體，奇幻生物不行

### 命名與搬家

- 專案從 `E:\Game01` 搬到 `E:\Knitguard`，推上 GitHub：`kevin890268/Knitguard`

### GPT 圖片 → 3D 模型
- 想用 GPT 生成美術圖，再轉成 3D 放進遊戲
- 做法選「**充氣布偶**」：去背 → 距離場 → 離輪廓越遠越厚，正反兩面貼同一張圖，像兩片毛氈縫起來塞棉花；剛好符合毛線手工風
- 輪廓交給貼圖的 alpha 切，網格很粗：一隻單位約 780 個三角形，1700 隻同時在場仍順
- 可選的第二張剪影（正面 + 側面）決定每一層的厚度，比例更像真的 3D
- 沒有圖就用原本的程式模型；開發者面板可以熱重載圖片、即時調厚度和解析度
- 換了新電腦：重新用 winget 安裝 Node.js LTS

### 第一隻羊人
- 綿羊兵的程式模型從四腳羊改成**擬人化羊人村民**（參考概念圖 `sheepan.png`）：雙腳站立、蓬鬆羊毛頭、捲角、側伸的耳朵、米白上衣＋棕色短褲、蹄手蹄腳、小尾巴
- 全部用低段數幾何體組合、平面著色（邊角分明），一隻約 600 個三角形；2000 多隻同時在場，繪圖約 1.4ms

### 羊人改用設定圖
- 程式拼的羊人和概念圖差太多 → 改走「外部美術」：新增 `.glb` 讀取（Blender／AI 圖片轉 3D 工具的模型），優先於圖片
- 在 .glb 做好之前，先用使用者的羊人設定表（`sheepan02.png`）：裁出正面、右側、背面三張，充氣成布偶
  - 新增**背面貼圖**：正反兩面拼成一張貼圖，輪廓沿用正面，背面看得到後腦羊毛和尾巴
  - 修正側面透空：輪廓外的頂點貼到輪廓線內側，側牆不再被 alpha 切出縫
- 地面的針織紋理改成獨立的淡版本（對比 0.45、針目放大一倍），不再那麼密

### 羊人 3D 模型（Tripo + 自己上色）
- 本機（RTX 3050 4GB）跑不動 AI 轉 3D；家裡的 RX 6700 XT 只能在 Linux 上做形狀，貼圖很難 → 先用 Tripo 線上版
- 自己寫的「多視角雕刻」形狀太粗，放棄；但它的**投影上色**很好用
- Tripo 低面數模型（2996 面，沒貼圖）＋ 設定表 5 個角度投影上色 ＋ 尾巴縮小 → `public/models/sheep.glb`
- 4000 面的模型 1847 隻同時在場只有 14 FPS（顯示卡畫不動）→ 之後考慮「近看 3D、遠看預渲染圖片」（They Are Billions 的殭屍就是圖片）

### 改成 2D 斜角
- 3D 每隻單位都要畫幾千個三角形，上千隻就卡 → 改成 They Are Billions 的做法：**2D 斜角、方格地圖、預先畫好的圖**
- 方格不是六角：模擬層（流場、碰撞、建築佔地）本來就是方格，完全不用改
- 羊人：載入時把 `.glb` 從斜角拍成 8 個方向；其他東西先用 Canvas 直接畫（使用者要求）
- 實測 4025 隻同時在場：繪圖 4.1ms、模擬 4.7ms（3D 版 1847 隻就只剩 14 FPS）
- 3D 版保留，網址加 `?3d`

## 2026-11-12　兵種 DEMO
- 三個種族的兵種定案（羊族、刺刺族、狗族，詳見 design.md）；使用者畫好 10 張兵種設定圖
- 圖片整理到 `art-src/<種族>/<兵種>/`，總表在 `art-src/README.md`
- 從設定圖的多視角裁出 8 方向遊戲圖（`public/sprites/<名字>/`）；設定圖上的「右側」常畫成臉朝左，一律以實際畫面為準
- 新的戰鬥規則（`data.ts`、`world.ts`）：輕甲／重甲、近戰／遠程防禦、固定數值的加成；遠程攻擊；技能：號角加攻、刺球衛自動縮球＋反傷、尖刺弩砲貫穿、陷阱、吠叫減速、救援犬治療
- 簡化：聖伯納只治療（還沒做「拖回後方」）；陷阱只有地刺一種；號角手還沒有設定圖（先用村民圖）；狗族遠程改成運輸兵，DEMO 不放
- DEMO：11 種兵各 10 隻圍在城堡旁，防守 2 波（第 1 波 900 隻、第 2 波 300 隻）
- 🐞 修好「敵人卡住」：① 出生時的隨機偏移可能落進封閉區域 → 改回出生點；② 大群推擠會把敵人擠過樹或石頭的對角縫，進到走不到城堡的區域 → 卡住偵測：待超過 1.5 秒就移到最近的可達格子
- 測試改用不開畫面的模擬（一場約 1 秒），避免筆電發熱
- 遠程攻擊不再畫線：箭、標槍、石頭用設定圖裁下的素材（`public/sprites/projectiles/`），尖刺弩砲的刺照設定圖畫；沿拋物線飛、圖片轉向飛行方向，**飛到才扣血**（投石車的石頭飛得慢、拋得高）

## 2026-11-12　軍隊指令（參考世紀帝國 4）
- 選取：點選、框選、Shift 加選、雙擊選同兵種、Ctrl+A 全選；選到的兵腳下有綠圈和血條，路線用虛線畫出來
- 指令：右鍵移動／攻擊、Shift 排路線、A 攻擊移動、R 巡邏、S 停止、H 堅守；編隊 Ctrl+數字
- 陣型（`sim/orders.ts`）：橫列／縱隊／散開；近戰在前、攻城器在後；同一排依左右位置分配，減少交錯；一起走時配合最慢的兵
- 尋路：每個指令算一張流場通往陣型中心，看得到自己的位置就直走；點到水裡或對岸 → 改成最近走得到的地方；朝「下一格中心」走，不會卡在石頭角
- 按鍵調整：數字鍵給編隊、A/S 給指令 → 建造改成 Z／T／B，鏡頭只用方向鍵（和右鍵拖曳）
- 🐞 找到敵人卡住的**根本原因**：流場的 Dijkstra 把距離存進 Float32Array 時被捨入，取出時誤判成過期而跳過，大片地圖算不到方向（測試地圖只算到 1282／4900 格）→ 改用 `Math.fround`，現在全部算得到
- 效能：DEMO 110 隻全部下攻擊移動＋第一波 900 隻，模擬平均 0.7ms／tick

### 試玩回饋
- 沒選部隊時 WASD 也能移動鏡頭（選了部隊 A／S 才是指令）
- 號角手的紅圈只在附近有敵人時才閃
- 投石車、尖刺弩砲移動用滑的（`wheeled`），不像步兵一跳一跳
- 攻擊移動時近戰兵「很近了卻不打」：原本只看自己 4 格左右 → 我方部隊視野改成 7 格（`PLAYER_SIGHT`），而且旁邊 3.5 格的隊友在打時會一起圍過去（`ASSIST`）
- **小隊**：一起下令（一起框選）的單位是同一隊（`units.grp`）。有隊員開打，16 格內的隊員全部圍過去，輔助兵（號角手、救援犬）跟到戰鬥點後面 3 格；不同小隊互不影響（數值在 `data.ts` 的 `SQUAD`）
- **重新審視所有貼圖**：設定圖裁切太緊（長槍兵的槍尖、弓箭手的弓、弩砲和陷阱工程師的旗子、狗狗騎兵背面的腳被切掉），而且排得很密的設定圖會裁進隔壁角度的槍。新工具 `tools/recrop-views.ps1`：在設定圖上找到原本的裁切位置 → 去背找出「主體」→ 照主體重新裁（留邊），隔壁的東西和文字塗成底色。10 種兵全部重裁；投石車、弩砲、弓箭手的去背容許值調高（米色漸層底）
  - 還留著的小問題：弓弦和身體之間、投石車三角架裡面被包起來的底色去不掉（顏色太接近羊毛，強行去會吃掉羊毛）
- **效能（沒有顯示卡加速的瀏覽器）**：軟體繪圖時成本跟「畫面像素數」成正比 → ① 自動解析度（一幀超過 20ms 就降，最低 50%，變快再調回來；狀態列看得到「解析度 %」）② 單位影子合成一次填色 ③ 降解析度時圖片取樣用 low ④ 下方資訊列內容沒變就不重寫（頭像圖片每次重寫都要重新解碼）。實測軟體繪圖一幀 67ms → 約 20ms
- **世界樹市鎮中心**：使用者提供五個階段的設定圖（`art-src/buildings/town-center/`）。原本的毛線城堡改成市鎮中心，可以進化 Ⅰ樹苗屋 → Ⅱ小樹屋 → Ⅲ繁榮樹城 → Ⅳ盟都 → Ⅴ永恆聖都（每階 💰150／300／500／800，耐久 ×1.4），每階換一張圖、越高階畫得越大。新工具 `tools/cutout-building.ps1`：從設定圖去背（背景是模糊的漸層光暈，用「顏色平滑地延伸」判斷）
  - Ⅳ、Ⅴ 的主視角左上角被標題橫幅蓋住，Ⅴ 背景還有星空和雲 → 先用不完美的版本，等乾淨的圖
- **ESC 暫停選單**：ESC 先取消（等待中的指令 → 建造工具 → 選取），都沒有就打開暫停選單（繼續／操作說明／重新開始／回標題），選單開著時遊戲暫停
- **功能表**（`ui/funcBar.ts`）：資訊列上面一小排分類（🏗️建造、⚔️部隊、🌳市鎮中心、⚙️系統），點一個分類，上面再多一排它的功能；再點一次收起來。建造從指令卡搬到這裡（按 Z/T/B/X 會自動打開「建造」），指令卡只放選到的東西的指令
- Chrome 很卡是因為 Chrome 沒開硬體加速（用 Microsoft Basic Render Driver 軟體繪圖），不是遊戲本身
